# Recorded native navigation bits

These fixtures retain the navigation bits recorded from satellites, including
the original GPS parity, D30* data inversion and GLONASS Hamming code. The `.bin`
streams below remove only source-container framing and padding. They were not
generated by the library serializer and their check bits were not regenerated.

| Stream | Recording | Complete messages | Meaningful bits | File bytes |
| --- | --- | --- | --- | --- |
| `gfz-gps-l1ca-2025-001-prn01-000000-001224.bin` | GFZ, 2025-01-01, GPS PRN 1 | 125 subframes, one 25-frame page cycle | 37,500 | 4,688 |
| `gpsd-glonass-sv12-superframe2158.bin` | GPSD, 2023-06-28, GLONASS slot 12 | 75 strings, one five-frame superframe | 6,375 | 797 |

Both streams concatenate meaningful bits MSB first, with no padding between
messages. Only the final byte has zero padding: four low bits for GPS and one for
GLONASS. They can be fed directly into the corresponding raw protocol parser.
The GPS `.frames.bin` companion retains the selected source rows, each with four
**trailing** padding bits; it is not the library's 38-byte canonical format, which
has four **leading** padding bits.

These are navigation-message bits after receiver demodulation, not RF/IQ samples.
GLONASS relative/bi-binary encoding and time marks have already been removed by
the receiver. Satellite identity and GLONASS frame context belong to the source
metadata and are not inserted into the native bit streams.

## Offline reproduction

From this directory, with Python 3.10+ and `pyarrow` installed for the GPS script:

```sh
python3 extract_gfz_recording.py Sources/NAVBIT-GPS-L1CA-2025-001-01-14400.arrow /tmp/gps-recording
python3 extract_glonass.py Sources/gpsd-ublox-glo.bin /tmp/glonass-recording
```

Compare the generated `.bin` and `.json` files byte for byte with this directory.
Both scripts pin source SHA-256 and validate check bits independently of
`Asv.Gnss`. They never invoke a production codec. The Python/Arrow dependency is
only for fixture maintenance; ordinary .NET tests require neither Python nor
network access.

## Automated tests

`RawNavigationRecordedStreamTest` loads these resources in the same way as the
other protocol recording tests. It checks:

- SHA-256 and sizes of the original containers and native streams;
- all 125 GPS subframes and 75 GLONASS strings, ordered IDs and GPS TOW;
- exact native bits after parsing and serialization, at read sizes 1, 7, 257 and
  4096 bytes, including messages sharing byte boundaries;
- every GPS parity equation and 397 D30*-complemented words;
- the complete captured page sequence, including a real GPS dummy page with
  `PageId=0`, NMCT, special-message bytes and future UTC parameters;
- all 584 GLONASS strings in the original UBX capture, its packet checksums,
  and the bit-for-bit source correspondence of the selected 75 strings;
- captured fifth-frame GLONASS context, B1/B2/KP and reserved-bit preservation;
- an incomplete final message without publishing that partial message.

The .NET tests pin the Arrow container and extracted-row hashes; decoding Arrow
itself is performed by the reproducible maintenance script. Expected native
bytes are sliced from the recordings, rather than produced by a serializer.
